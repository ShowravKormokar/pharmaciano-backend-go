# Pharmaciano ERP — OpenAPI-First API Contract

Pharmaciano's REST API is defined **contract-first**: a split OpenAPI **3.1** YAML tree under [`api/openapi/`](../../api/openapi) is the single source of truth. Go code, typed handlers, SDK clients, interactive docs, linting and breaking-change detection are all **derived** from it. This replaces the previous annotation-driven `swaggo/swag` workflow.

Nothing about the design leaks into our handlers: there are **no OpenAPI/`swag` annotations above any Go function**. Handlers stay plain Gin; the contract lives entirely in the YAML.

---

## 1. Why OpenAPI-first (replacing swaggo)

`swaggo/swag` generated docs from annotations scattered across handlers. As the API grew to hundreds of endpoints that model broke down:

| Concern | swaggo/swag | OpenAPI-first (this repo) |
|---|---|---|
| Single source of truth | None — annotations drift from reality | The YAML contract in `api/openapi/**` |
| Editor views the doc | Docs live in Go comments | A real YAML tree, versionable, diffable |
| Go types | Hand-written, unverified against doc | Generated by `oapi-codegen` from the contract |
| Validation | None at the edge | `kin-openapi` middleware rejects off-contract requests |
| Linting | None | Redocly recommended ruleset |
| Breaking-change guard | None | `oasdiff` blocks removals/re-wires in CI |
| Interactive docs | swagger-ui (flaky) | Scalar reference |
| Client SDKs | None | Generated Go SDK + any-language via contract |

## 2. Architecture

```
                    api/openapi/**   (split OpenAPI 3.1 YAML — SOURCE OF TRUTH)
                          │
            make oapi-lint │ Redocly lint
            make oapi-bundle│
                          ▼
              build/openapi.bundled.yaml   (single-file, self-contained)
                          │
      ┌───────────────────┼───────────────────────┐
      ▼                   ▼                       ▼
  oapi-codegen        kin-openapi             oasdiff
  (Go models+        (runtime request        (breaking-change
   strict-server)    validation)             detection)
      │                   │                       │
      ▼                   ▼                       ▼
 internal/api/gen    internal/api/server     CI gate on PRs
      │                (validator.go)
      ▼
 gin router + strict handlers
```

Three downstream consumers of the **bundled** spec (never of the split tree):

1. **`oapi-codegen`** → typed Go models + Gin strict-server interfaces.
2. **`kin-openapi`** (behind `-tags oapival`) → runtime request/response validation.
3. **Scalar / Redocly / openapi-generator** → interactive docs and cross-language SDKs.

The **split tree** is only ever consumed by Redocly for bundling. Everyone else gets one file.

## 3. Directory layout

```text
api/
├── openapi/                          # THE contract tree
│   ├── openapi.yaml                  # root: info, servers, security, 37 paths, components map
│   ├── paths/
│   │   ├── auth.yaml                 # /auth/{login,refresh,...,mfa/*} (17 endpoints)
│   │   ├── users.yaml                # users CRUD + status + role/branch assignment (10)
│   │   ├── branches.yaml             # branches CRUD (6)
│   │   ├── organizations.yaml        # organization current/id/summary (4)
│   │   ├── warehouses.yaml           # warehouses CRUD + per-branch (6)
│   │   ├── rbac.yaml                 # roles + permissions (8)
│   │   └── health.yaml               # /health liveness (public)
│   ├── components/
│   │   ├── schemas/                  # common, auth, user, branch, organization, warehouse, rbac
│   │   ├── parameters/               # pagination.yaml (query+header), path.yaml
│   │   ├── responses/                # error.yaml (9 reusable error responses)
│   │   ├── headers/                  # pagination.yaml (RateLimit-*, XTotalCount, Sunset…)
│   │   ├── securitySchemes/          # bearer.yaml
│   │   └── examples/                 # error.yaml (12 runnable examples)
│   └── config/
│       ├── oapi-codegen.yaml         # server + models generator config
│       ├── client.yaml               # Go SDK generator config
│       ├── redocly.yaml              # lint/bundle ruleset
│       └── oasdiff.yaml              # breaking-change policy
├── scalar/
│   └── index.html                    # self-hosted interactive reference UI
├── scripts/openapi/validate.py       # fast, dep-free ref-gate (CI pre-check)
└── build/openapi.bundled.yaml        # GENERATED — never commit edits
```

### Why split YAML + JSON-pointer `$ref`

Domain files (`auth.yaml`, `users.yaml`, …) keep their full set of `path` items together, so the tree stays readable as it scales to hundreds of endpoints — rather than one file per endpoint. The root `openapi.yaml` pulls each path via an escaped JSON-pointer ref:

```yaml
paths:
  /auth/login:
    $ref: 'paths/auth.yaml#/~1auth~1login'
```

`~1` escapes the `/` in the anchor (JSON Pointer semantics on a top-level path key like `/auth/login`). The same mechanism scales to any future `x-versions` split.

## 4. Adding a new endpoint

This is the **prescribed** flow — contract first, code after.

1. **Open the spec.** Edit the relevant file under `api/openapi/paths/` (or create a new one) and add the `operationId`, `parameters`, `requestBody`, `responses`.
2. **Add/reuse schemas.** New body DTOs go in `api/openapi/components/schemas/`; prefer composing existing ones. Reuse the reusable `responses.error.yaml#/…` and pagination parameters wherever possible.
3. **Validate.** `make oapi-check` (fast) then `make oapi-lint` (Redocly).
4. **Bundle + generate.** `make oapi-bundle` then `make oapi-generate`. This produces typed request/response objects (`internal/api/gen/v1`) and — if you opt in — a generated Gin handler to implement in the strict-server adapter.
5. **Serve it.** For endpoints you want typed, add a method to `StrictHandler` (`internal/api/server/strict.go`) and wire it to your service. Otherwise keep the legacy Gin handler: the kin-openapi validator still enforces the contract on the way in.
6. **Contract a baseline.** When this becomes a published contract, run `make oapi-diff BASE=…` to confirm you haven't broken existing consumers.
7. **Regenerate the client** if teams consume the Go SDK: `make oapi-client`.

> **Rule:** never hand-edit anything under `internal/api/`. It is regenerated and any local change is overwritten and flagged as drift by CI.

## 5. Runtime request/response validation

`internal/api/server/validator.go` implements a [`kin-openapi`](https://github.com/getkin/kin-openapi) middleware that validates each inbound request against the **bundled** spec:

- path, query and header parameters
- request body shape (type + against `schema`)
- (opt-in) response body

It runs after global middleware and before any module route. On rejection it returns the standard error envelope with code `VALIDATION_ERROR` (HTTP 400), so failure modes are uniform across the API.

It is compiled only under the **`oapival`** build tag:

```sh
go build -tags oapival ./internal/api/server/...
make oapi-validate
```

The default build (`go build ./...`) stays stdlib-only — matching the repo's `-tags grpc` / `-tags service` precedent. The strict-server adapter (`strict.go`) is similarly gated behind `-tags oapigen`. When both tags are needed (validated, typed pipeline), build with `-tags oapival,oapigen`.

## 6. Generated Go types & server

`make oapi-generate` runs [`oapi-codegen`](https://github.com/oapi-codegen/oapi-codegen) with [`config/oapi-codegen.yaml`](../../api/openapi/config/oapi-codegen.yaml):

- `models` — request/response structs
- `embedded-spec` — the bundled YAML compiled into the binary (for `openapi3.ShowSpec`/inspection)
- `gin-server` — `Router` interface + Gin registration helpers
- `strict-server` — typed `StrictServerInterface` (`XxxRequestObject` → `XxxResponseObject`)

The generated Gin handlers write the wire response from `Xxx200JSONResponse{…}`. `internal/api/server/strict.go` is the reference adapter routing those typed objects to the real service layer and wrapping results in the `{success, data, pagination, error, meta}` envelope from `pkg/response`. It's written as a documented, partially commented reference — reconcile the concrete response-type names against the real generator output on the first run.

## 7. Interactive docs (Scalar)

[`api/scalar/index.html`](../../api/scalar/index.html) hosts the **Scalar** API reference UI — a modern, self-hosted, searchable docs page. It loads the contract directly:

```sh
make oapi-bundle
make oapi-serve     # → http://localhost:6060
```

Two ways to open it:

```sh
make oapi-bundle && make oapi-serve   # static dev view -> http://localhost:6060
```

Under Docker the running API serves it directly at the same origin you call, so Try-it posts to the live backend with no CORS dance:

```sh
make docker-up
# -> http://localhost:8080/api-docs/            (Scalar UI)
# -> http://localhost:8080/api-docs/openapi.yaml (bundled spec)
```

`internal/router/docs.go` mounts `/api-docs` (Gin `Static`) from `api/scalar`; the Dockerfile copies that dir into the image. The viewer spec `api/scalar/openapi.yaml` is a self-contained bundle (all refs inlined) regenerated by `make oapi-bundle` via `scripts/openapi/bundle.py`, kept separate from the redocly `build/openapi.bundled.yaml` that feeds `oapi-codegen`.

Same UI family powers many production API portals; it renders the security schemes, the reusable error catalogue, pagination headers, and the per-endpoint request/response schemas straight from the bundled YAML.

## 8. Versioning (v1 → v2)

The root spec declares `servers` for `http://localhost:8080` and `https://api.pharmaciano.com`, and the Gin router mounts modules under `/api/v1` ([`internal/router/v1.go`](../router/v1.go)).

- **Backward-compatible evolution** is the default: add `optional` fields, add endpoints, broaden `anyOf`/`enum`. This is **enforced** by `oasdiff` in PR CI.
- **Breaking changes** (`v2`) are introduced by adding a parallel `/api/v2` module and a new paths namespace — never by mutating v1 paths in place.
- Deprecated endpoints carry `deprecated: true` plus `Sunset`/`Deprecation` headers (see `components/headers/pagination.yaml`). Removed endpoints return `410 Gone`.

The 3.1 spec supports this cleanly: `info.version`, per-path `x-versioning` notes, and whole-tree `$ref` composition make a v2 layer an additive job, not a rewrite.

## 9. Migrating from swaggo/swag

1. **Remove** `swag` annotations from handlers (plain Gin handlers stay as-is).
2. **Delete** the `make swagger` target (now `oapi-*` targets, see `Makefile`) and stop generating `docs/swagger`.
3. **Port** each endpoint's payloads into `api/openapi/**` using the new schemas as cribs.
4. **Replace** swagger-ui with Scalar (`make oapi-serve`).
5. Any consumer of `docs/swagger/swagger.json` should point at `build/openapi.bundled.yaml` or `api/scalar`.

## 11. CI

[`.github/workflows/openapi-ci.yaml`](../workflows/openapi-ci.yaml) runs on PRs that touch the contract or generated code:

- **validate** — fast `validate.py` gate, then Redocly lint on the bundled spec
- **generate** — bundle → `oapi-codegen` (server + client) → **drift check** (generated output must equal the commit) → build both the default tag and `oapival` tag
- **diff** — `oasdiff` against the base contract; **blocks breaking changes** before merge

---

## 12. Production readiness at scale

- **Reusable building blocks** keep hundreds of endpoints DRY: shared schemas, reusable `responses/*`, pagination parameters, security schemes, and a 12-example error catalogue.
- **Per-endpoint security** is declarative: `bearerAuth` marks protected paths; public probes (`/health`) have none.
- **Generated output is disposable** — revert/regenerate rather than hand-fix, and CI catches any drift.
- **Polyglot consumers** get SDKs from the same single contract (`openapi-generator`/Fern/Stainless can be pointed straight at the bundled YAML), alongside the in-repo Go client.
